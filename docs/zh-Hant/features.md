## 完整清單

**訊號路徑的位元精確是可以證明的。** 不是「我們覺得應該沒有重採樣」—— 是量出來的。
`yunaudio-cli selftest` 送一段 24 位元的偽隨機序列走完整條路徑，從 loopback 讀回來，
從資料本身還原延遲，再逐一比對每個取樣：

```
bit-exact: 261400/261400 samples identical, delay 872 frames
clock lock held at 0.999986 throughout
```

方法寫在 **[MEASUREMENT.md](../../MEASUREMENT.md)** —— 序列是什麼、為什麼是 24 位元、
延遲怎麼從資料裡還原，以及同樣重要的：這個量測**不能**證明什麼。

之所以做得到，是因為 YunAudio 自己帶一個虛擬裝置，不是借別人的。CoreAudio 驅動可以用
`GetZeroTimeStamp()` 定義自己的時鐘，所以這一個把取樣時鐘推導自「這個 app 實際在擷取
的那支麥克風」。於是兩個裝置同步前進，HAL 的漂移補償可以關掉，路徑上沒有任何一段重採樣。
第三方的 loopback 裝置做不到 —— 它根本不知道你在意的是哪支麥克風。

那個 `0.999986` 是你麥克風的石英誤差，量出來的：慢了百萬分之 14，換算成每小時 50 毫秒
的漂移 —— 如果沒有人去修正它。

**而且這個檢查你可以自己跑。** 它在「設定 → 診斷」裡，不只在 CLI：按一個按鈕，app 就把
序列送過你自己的路徑，並替回來的東西評分。在沒有時鐘鎖定的路徑上，它會報出真正的情況
—— 已重採樣、還原出的 loopback 延遲、以及轉換的幅度 —— 而不是通過或失敗。

**它會告訴你路徑的實話。** 位元精確、已重採樣，還是已處理；實測的來回延遲；時鐘鎖定
現在到底有沒有撐住。你一開人聲隔離，它就會說出來，並且停止聲稱位元精確 —— 因為處理
訊號和「不動它」正好相反。

**響度用廣播標準量。** 峰值表回答的是「會不會削波」。它回答不了任何在直播或錄音的人
真正的問題，也就是「我跟別人一樣大聲嗎」—— Discord 正規化到約 −18 LUFS、YouTube −14、
廣播 −23。YunAudio 依 ITU-R BS.1770-4 量響度，那正是那些平台用的同一個標準：K 加權、
400 毫秒區塊、75% 重疊，以及那個讓停頓不算進去的兩段式閘門。它讀瞬時、短期與整體，
然後把有用的那部分講成一句話 —— 你離所選的平台還差多少，以及該往哪邊移。

算術是對著標準檢查的，不是對著自己：一個 1 kHz 正弦波讀出的 LUFS 就是它自己的 RMS
電平、振幅加倍會剛好多 6.02、在 48 kHz 與 96 kHz 下讀數相同、而段落之間的靜音不會把它
往下拖。**macOS 上這個類別裡沒有別的軟體量響度。**

**你可以從頻譜上讀出頻率。** 二十四個對數間隔的頻段，配一條頻率軸，所以畫面說的是
「是什麼」而不只是「有多少」：60 Hz 的哼聲、100 Hz 以下的桌面敲擊、堆在 7 kHz 的齒音。
而且是校準過的，不只是排序過的 —— 一個已知振幅的音會以它自己的分貝值回來，那個斷言
在這裡抓到過一個真的變換錯誤。

**它會自己調平，而且知道自己在聽什麼。** 自動增益之所以有它現在的名聲，只有一個原因：
包絡追隨器分不出人聲和電風扇，所以它把每一個停頓都用來把增益往房間噪音裡推，然後在你
再開口時把你壓下去。**它的問題在量測，不在控制迴路。**

YunAudio 一邊依廣播標準量響度，一邊在同一份訊號上跑 Apple 的裝置端聲音分類器 ——
macOS 內建那個三百類的模型。調平器只在模型回報「說話」時移動，每秒 1.5 dB、在一個死區
之內、上限 15 dB。停頓、打字和空調不是關於「任何人有多大聲」的證據，所以它在那些時候
不動。介面會顯示模型聽到了什麼，所以它是一份診斷而不是一個黑盒子：你聲音底下出現
*打字* 就是該開閘門的理由。

那個控制迴路是一個沒有任何相依的值型別，配十三個測試 —— 因為一個「只被人對著麥克風
講話試過」的調平器根本沒有被測過：它必須收斂、不能過衝、不能來回擺盪，而且要拒絕對著
靜音動作。分類器是對著真的合成語音檢查的，不是只對著它自己的標籤表。

**KTV 不預設中文歌沒有歌詞。** 先用 Music 自己的歌詞和本機 `.lrc`，再並行去問 LRCLIB、
QQ 音樂、網易雲音樂和 lyrics.ovh。驗證通過的時間軸勝出，並取消還在跑的較慢請求；簡體
與繁體的中介資料、現場版與電視演出的標記都會被比對，而不會把原唱錯誤地接到伴奏上。
Spotify 本身完全沒有公開歌詞屬性，但一次真實執行 —— 黃霄雲的《年少心動雨季》——
透過中文來源找到了一份 265 秒、超過六十行的時間軸。

評分會說出它的參考是什麼。同名的 MIDI 檔是精確旋律；擷取到的原唱是自動的、從音訊推導
出來的參考；而伴奏本身只能誠實地提供調性、音準和樂句時間，因為它不含人聲旋律。每支
麥克風保有自己的音高歷史與分數，所以對唱是**兩份實際量到的表演**，而不是從一份混音裡
猜出兩個人。Music 和 Spotify 透過它們的 scripting dictionary 提供受支援的 now-playing
中介資料。其他被擷取的播放器，在散布用的 App ID 啟用了 ShazamKit 服務時，走公開的
ShazamKit 辨識；ad-hoc 建置會直接說出那個簽章需求，而不是去重試一個註定不會成功的
目錄請求。

**直接監聽是真的直接。** 透過通訊軟體聽自己會慢三十毫秒，那已經足以讓人講話打結。
這裡的監聽是同一個聚合裝置上的第二個目的地，所以它是一個 IO 週期加上輸出裝置本身 ——
量到進顯示器的音訊是 11.2 毫秒，進任何驅動正常的裝置是 2.7 毫秒。它**不受主推桿影響**，
因為主推桿是送給對方的電平，把它拉下來不應該讓你聽不見自己的聲音；但輸入電平和靜音
**會**影響它，因為把麥克風靜音本來就應該讓你聽不到它。兩條規則都是直接對著即時回呼
斷言的。

**變聲器改變的是聲音，不只是音高。** 移調會把整個頻譜一起搬 —— 基頻，以及疊在它上面的
喉腔與口腔共振 —— 而耳朵把那讀成「一顆比較小的頭」，不是「另一個人」。這就是為什麼
每一個移調器都做出花栗鼠。一個高大的男人和一個嬌小的女人可以唱同一個音；不同的是他們
的共振峰坐在哪裡。

所以共振峰是獨立移動的，那是 macOS 上沒有任何東西提供的，這裡從頭寫出來：從對數頻譜的
低 quefrency 部分估出頻譜包絡、沿頻率軸拉伸、再除回去，讓諧波 —— 因此也讓音高 ——
留在原來的位置。測試會斷言這件事的**兩半**，因為一個只檢查「共振峰有動」的測試，對一個
普通的移調器也會通過。旁邊還有一個音色階段，用環形調變、抽取與軟削波做出來：機器人、
無線電、怪物、數位破碎、外星人。

**變聲要是一個聲音，不是兩個旋鈕。** 音高和共振峰是分開的階段，因為它們是分開的物理
事實 —— 但沒有人想被告知這件事，他們想要的是聽起來像另一個人，而那是一組**特定**的
設定。成年男性的說話音高大約在 110 到 130 Hz，成年女性大約 200 到 220，差不多是一個
五度；但只移五度的音高聽起來明顯就是處理過的，因為共振峰沒有跟著動。女性的共振峰大約
高 15 到 20 個百分比，來自一條大約短了那麼多的聲道。兩者一起移，耳朵就不再聽到「效果」。

這些預設是量出來的，不是宣稱的：一個合成的男聲通過「變高」預設，出來時音高上升了所宣稱
的 500 音分，而且頻譜重心跟著一起上升 —— 同一份訊號、走真實的處理鏈。

**它不是**神經網路的聲音轉換。像 fish-speech 或 RVC 那樣的東西是學一個目標說話者再重新
合成，那是另一件事、而且是更好的一件事 —— 但它需要一個模型、一條 GPU 流程，以及遠超過
一百毫秒。那些沒有一樣塞得進 2.7 毫秒的 IO 期限。今天出貨的每一個即時變聲器做的都是
這裡做的事；這一個把它說出來。

**逐字稿知道哪句是誰說的，而且不用猜。** 每一個做對話轉錄的產品都會在語者分離這件事上
公開地留保留 —— 因為從聲音裡推斷「誰在說話」是一個猜測，而且錯得夠頻繁，足以成為人們
抱怨的那件事。

這個應用程式沒有那個問題，而且**不是因為它解決了它**。麥克風是一個來源，每個被擷取的
應用程式是自己的一個 process tap，在任何東西到達模型之前就已經分開了。每個來源一個
轉錄器，而語者標籤是**接線**，不是推論。`SpeechTranscriber` 是 macOS 自己的模型，設計
給持續數小時的轉錄而不是短查詢，而且它跑在裝置上：沒有按分鐘計費、沒有上傳、沒有金鑰。

**第三方 Audio Unit。** 這才是音訊領域裡「外掛」的意思，而它也是唯一一個「載入別人的
程式碼」是正確答案、而不是一種繞遠路避開設定檔的地方：格式本來就存在、系統會審查並
沙箱它、而且已經有幾千個裝在機器上了。它們插在一個位置，而那個位置不是隨便選的 ——
在這個應用程式所有塑形之後、限幅器之前，因為限幅器的整個工作就是「不讓下游看到任何
需要削掉的取樣」。任何跑在它之後的東西都能把訊號重新推過滿刻度，所以不論使用者怎麼拖，
外掛都不能被允許放在那裡。

一個必須跑在自己處理程序裡的單元，會讓每一次 render 變成一次 XPC 往返 —— 那在混音工作
階段裡沒問題，在一個期限 2.7 毫秒的回呼裡就不行。這件事會在它進入路徑**之前**就講清楚，
而不是事後才發現。

**裝置是用文件描述的，不是用程式碼。** CoreAudio 會說一支麥克風有三個輸入聲道，然後對
「那三個上面是什麼」一句話也沒有。要知道 Seiren V3 Pro 的三個分別是「處理後的音頭」、
「乾的音頭」和「麥克風自己擴展器的輸出」，得把那東西拆開來看 —— 而那份知識以前是編譯
進去的，所以每一支新麥克風都意味著一次程式碼改動和一次發版，只為了一張字串表。現在它
是一個 JSON 檔，而任何放進
`~/Library/Application Support/YunAudio/Devices` 的東西都會被疊加載入。

**刻意是資料而不是外掛**：一份設定描述硬體，它不執行；而從一個資料夾載入程式碼會意味著
簽章、版本管理、穩定的 ABI，以及一個壞掉的檔案有辦法把音訊系統一起帶下去。

**來自 Apple 自家模型的人聲隔離。** `AUSoundIsolation` 就是 FaceTime「語音隔離」背後的
那個模型，在裝置上跑、免費，而這個類別裡沒有別的路由器把它當成一般的麥克風處理器公開
出來。這裡量到：增加 56 毫秒延遲，CPU 用掉不到 IO 期限的四分之一。

**兩級增益，順序是對的。** 麥克風自己的增益發生在硬體裡、在它的轉換器之前，所以把它
調高不佔用任何動態餘裕；而之後的數位電平只能放大轉換器已經決定好的東西，包括雜訊。
兩者都在這裡，而硬體那一級在前面 —— 那才是有意義的順序，也是 macOS 上沒有別的軟體
擺在你面前的順序。

它只在裝置公開了可設定的增益時才出現，而「哪些裝置是那些」這件事花了兩次才問對。這裡
最初的答案 —— 而且逆向工程的紀錄也同意 —— 是 Seiren **V2 X** 公開了一個、而
**V3 Pro 沒有**，所以在 V3 Pro 上只剩數位電平。**那是錯的。** CoreAudio 是**按 element**
公開一個裝置的控制項的，master 是 element 0，而只問 master 看起來像是可以用，因為多數
裝置就在那裡回答。V3 Pro 回答在 **element 1、2 和 3** —— 一個音頭 tap 一個 —— 每一個
都帶著它固件所記載的完整 **0 到 +36 dB**。沒有人問對 element。

**零延遲監聽，由麥克風自己做。** 同一次清查翻出一件 macOS 上沒有任何東西提供去移動的
東西：Seiren 公開了一個 play-through 電平，那是裝置在矽片裡把自己的輸入送回自己的耳機
孔。那才是麥克風包裝盒上「零延遲」真正的意思 —— 訊號從來沒有到達電腦。這個應用程式
自己的監聽是 2.7 毫秒，那很好，但不是零。Razer 的軟體在 Windows 上透過一個 USB 請求
碰到它；這裡沒有 Synapse，而在此之前根本沒有任何辦法移動它。

它是被**提供**而不是被**開啟**的，因為回來的是**未經處理**的音頭：這裡的任何處理都不
可能在裡面，因為那些還都沒有發生。

**它知道你麥克風的那些聲道到底是什麼。** CoreAudio 報告 Seiren V3 Pro 有三個輸入，
然後對上面是什麼一句話也沒有。它們是處理後的音頭、乾的音頭，以及經過麥克風自己擴展器
之後的音頭 —— 那個擴展器位於轉換器之前，所以它在任何東西可能削波之前就先去掉房間噪音。
選擇器會把三個都命名，並說出每一個是幹什麼的。那份對應是從裝置自己的模組傾印它的內部
拓樸得來的，而 macOS 上沒有別的東西會告訴你。

**裝置被拔掉時它會繼續。** 一支通話中掉出來的 USB 麥克風，以前會讓路由器停下來等。
它現在會換到「最近用過、而且確實在場」的那支麥克風，說出它正在頂替哪一個裝置，並在原來
那支被插回去的那一刻換回去 —— 除非你在這期間自己選了別的，那會終止這個接管，因為那時候
把你換回去是在推翻一個決定，而不是在復原一個意外。

**擷取應用程式音訊不需要額外驅動。** 透過 `AudioHardwareCreateProcessTap` 擷取任何
應用程式，並且可以選擇同時把它原本的輸出靜音。Loopback 和它的同類為了這件事需要自己的
外掛；這裡它是一個有文件的 API。

**裸引擎很輕，但完整應用仍需要優化。** 最新記錄的六分鐘立體聲路由基線是在 128 frame
下使用單核心的 0.42%、常駐 7.1 MB；打開視窗的完整應用約為 18% 與 180 MB。兩組數字都必須
一起比較，只引用引擎會掩蓋仍待完成的 UI 效能工作。

**即時路徑不做任何記憶體配置。** 是驗證過的，不是宣稱的：配置器上掛了一個攔截器，計數
任何在 IO 執行緒上配置的東西。在最佳化建置下、數千個週期裡是零。（要量 release 建置 ——
debug 建置自己的邊界與獨佔性檢查會配置記憶體，而那跟出貨的程式碼無關。）
